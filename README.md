# xinOVO

这是 OVO 的静态网页项目。仓库根目录中的 `index.html` 是小型装配入口，下载仓库后可以直接双击打开，不需要启动开发服务器。

维护发布时请先查看 [提前上传记账](docs/release-tracking.json)。其中未记入正式版本的功能须纳入后续大更新，并按功能 ID 去重；提前上传不更新正式日志，也不消耗大更新的功能记录。

## 修改页面

页面源码位于 `src/html/`，入口模板是 `src/index.template.html`。请修改对应功能片段，不要直接修改生成后的根目录 `index.html`。

```powershell
npm install
npm run build
npm run check
```

`npm run build` 会把 HTML 片段转换为 `js/generated/html/` 下的本地经典脚本，并生成紧凑的根目录入口；还会重新生成需要保持私有作用域的兼容脚本。页面片段会在业务初始化前同步装配，因此不依赖 HTTP 服务或运行时 `fetch()`。`npm run check` 会检查装配后的完整 HTML 结构、重复 ID、本地资源、已移除的登录验证标记和全部 JavaScript 语法。

## JavaScript 结构

「主屏幕自定义 → 系统美化 → 聊天输入框避让」默认关闭。开启后，自动模式根据键盘弹出后的可见区域调整聊天室，可额外上移 0–160 px；关闭自动模式后，可手动设置上移 0–500 px。仅在聊天打字时生效，不移动系统键盘，不改写现有美化代码，关闭总开关恢复原布局。设置随全局设置保存并纳入完整备份。`npm run test:keyboard` 使用隔离数据检查开关、模拟键盘、手动调节、恢复、屏幕切换和保存失败；手机键盘仍需实机验证。自动处理依据：[Chrome 的键盘与可见区域说明](https://developer.chrome.com/blog/viewport-resize-behavior)。

单聊的聊天设置支持角色自主修改备注与拍一拍。四个权限按角色分别保存、默认关闭：「设定」里可允许修改角色自己的备注、给用户的独立备注；「功能 → 拍一拍」里可分别允许修改角色与用户的被拍后缀。拍一拍修改需要开启总开关，不要求允许角色主动拍。新增「TA 给我的备注」可查看、手动修改或清空，不改变「我的名字」、真名或其他角色的资料。修改随聊天回复自然触发，不额外调用 AI；成功保存后显示居中提示，历史拍一拍保留原有快照。`npm run test:character-profile` 验证权限组合、角色隔离、保存失败恢复、提示词模式与回复处理。

`npm run test:character-profile-browser` 使用隔离测试数据验证实际设置读取和保存、角色切换、资料同步、未保存输入保护、备注引号的文字显示，以及 320／390／768 像素宽度和夜间模式。需要在 `NODE_PATH` 中提供 Playwright，`OVO_TEST_CHROMIUM` 可指定已安装的 Chrome 或 Edge。

魔法屋按「系统提示词」「动态能力」「运行与通知」分栏。页签切换保留未保存内容；提示词只折叠连续同类条目，不改变编译顺序，仍支持跨分类上下移动、完整源码、旧预设和模板导入导出。`npm run test:magic-room` 使用独立内存数据检查编辑、保存、预设、动态能力、移动端布局和暗色模式，需要在 `NODE_PATH` 中提供 Playwright；`OVO_TEST_BROWSER=webkit` 可切换 WebKit，`OVO_TEST_CHROMIUM` 可指定 Chromium 浏览器路径。

HTML 互动消息支持在编辑窗口直接粘贴带 JavaScript 的网页，运行预览并保存；包含独立状态、展开查看、六种示例及模板导入导出。用法、接口、资源配置和验证见 [HTML 互动消息](docs/interactive-messages.md)。

- `js/settings/`：聊天设置、API、外观、预设和 TTS。
- `js/modules/chat-ai/`：上下文、请求、回复处理、提示词、Token 统计和通话回复。
- `js/modules/chat-render/`：消息列表、消息气泡、消息操作和图片生成。
- `js/modules/forum/`：账号、帖子、设置、私信和 AI 互动。
- `js/modules/theater/`：剧场数据、编辑、生成、分享和角色剧场。
- `js/modules/tutorial/`：引导、数据工具、备份恢复和 GitHub 备份。
- `js/modules/peek/`：偷看手机的设置、应用渲染、提示词与生成。
- `js/core/`、`js/data/`：公共工具、默认数据和 IndexedDB 持久化。
- `js/group-chat/`、`js/modules/journal/`、`js/modules/worldbook/`：群聊、日记和世界书。
- `src/js/modules/memory-table/`：结构化记忆的可维护源码片段。由于该模块依赖单个 IIFE 的私有状态，构建时会原样拼装为 `js/modules/memory_table.js`。
- `src/js/modules/avatar-recognition/`、`src/js/modules/video-call/`：依赖单个闭包或模块对象的兼容源码片段，构建时原样拼装为对应运行文件。
- `src/js/settings/chat-settings/`：聊天设置大函数的可维护源码片段，构建时原样拼装，避免拆开函数作用域造成回归。

所有运行时脚本仍按原来的经典脚本顺序同步加载，以保持原有全局函数、内联事件和初始化行为。

## 服务器推送

“运行与通知”现在提供设备订阅登记、独立的服务器推送测试和取消订阅。GitHub Pages 等静态托管需要另外部署 `server/push/` 的推送服务，填写服务根地址和客户端 Token 后连接。它可以发送服务端通知；角色在网页关闭后继续生成消息仍需另外实现服务端任务。部署和验收见 [服务器推送说明](docs/push-notifications.md)。

`node scripts/test-push.mjs` 验证登记、鉴权、持久化、失效清理和断开，实际设备送达需部署后测试。

## 动态记忆

从「动态 → 右上角设置 → 管理动态记忆」选择角色，可搜索并单条、多选或全部清除该角色看过的动态记录，包括已经删除的动态和 Story。清除会移除对应隐藏旁白，并阻止该条动态的正文、观看、互动和删除记录继续进入该角色上下文及自动互动；原动态和其他角色的记忆保留。普通聊天、总结及其他记忆里已经提到的内容需要另行删除。清除范围按动态 ID 区分，重新发布是新的动态。`node scripts/test-moments-memory.mjs` 验证角色隔离、已删动态、保存失败回滚和旧请求返回。

## 音乐

从桌面的「音乐」进入首页、搜索和音乐库。默认日间外观，右上角日月按钮切换日间／夜间并记住选择。搜索选择曲库，音乐设置选择服务与音质；支持歌单、收藏、队列、歌词同步与时间校准、定时停止、锁屏媒体控制，离开音乐页面后可以通过小型播放器继续控制。

音乐服务直接由浏览器访问，支持预设服务及自定义 Meting、网易云增强、GD Studio、OpenMusic 兼容地址。服务可用性、曲目权限、音质和跨域访问取决于接口；失败可重试、切换线路，自动备用仅使用同平台歌曲 ID。需要 Key 的服务由用户填写，音乐资料导出不包含 Key 或临时播放地址。

「音乐库 → 导入与导出」支持在线歌曲／歌单链接、音乐资料 JSON 和本地音频。本地音频每首不超过 30MB；歌词与封面采用和音频相同的文件名（例如 `歌手 - 歌名.mp3`、`歌手 - 歌名.lrc`、`歌手 - 歌名.jpg`），可以一起导入。导出时选择是否打包本地音频；没有打包的音频需要在新设备重新导入。完整 OVO 备份也包含音乐库与本地音乐资产。

播放页耳机按钮邀请现有角色一起听，用户输入后沿用该角色的聊天 API 生成对话，也可以把当前歌曲资料分享到角色聊天。语音和通话会按设置暂停音乐，用户手动暂停后不会被自动恢复。

`node scripts/test-music.mjs` 验证曲目、服务、歌词、导入导出与声音协调；`node scripts/test-music-browser.mjs` 使用隔离数据验证浏览器中的播放、备用线路、角色对话、文件导入导出和日夜布局，需要在 `NODE_PATH` 中提供 Playwright，`OVO_TEST_CHROMIUM` 可指定浏览器路径。

## 拉取应用更新

「教程」的 GitHub 仓库备份下方提供「拉取最新文件」。更新前会提醒先备份；下载中可以取消，文件校验完整且当前数据保存成功后才切换缓存并刷新一次。失败时保留当前版本，聊天记录、角色、设置及仓库备份配置不会被清除。

更新自动使用当前站点的部署路径，支持 `/OVO/`、`/xinOVO/`、`/TUT/` 及根路径，互不清理缓存。发布时需执行 `npm run build` 并一起上传 `sw.js`、`sw-assets.js` 和全部生成的应用文件；按钮只会拉取当前链接已经发布的内容。`npm run test:service-worker` 验证更新流程和原有通知功能。

## 生图锁脸

在角色聊天设置的「拓展」生图区域开启「生图锁脸」，默认取当前角色头像作为人物参考，也可上传一张单人、面部清晰的图片。保存设置后，角色本人单人照片和视频通话画面自动使用参考；换头像不改变已选参考。风景、物品、其他人物和多人合照不自动套用角色参考，历史照片不会自动重生成。

同一区域的「USER 生图锁脸」单独保存本私聊的用户参考图，默认取本聊天的 USER 头像，也可上传图片。角色发来只拍 USER 的生图照片时使用这张参考图，角色单人照仍使用角色自己的设置。USER 参考图随数据备份保存，分享用的 PNG 和 JSON 角色卡会省略该设置。

支持 NovelAI V4.5 精准角色参考、Gemini 图片模型及支持图像编辑的 GPT Image 接口。NovelAI 锁脸请求不叠加全局参考与 VIBE，但保留其配置和原有入口；Stability 当前接法和其他不支持参考输入的模型会明确提示。参考图片可能额外计费，人物一致性取决于模型与参考图。`npm run test:face-lock` 验证参考输入、人物主体、后台队列隔离和错误处理。

## 查手机历史与联系人知晓

查手机首页和消息列表的「历史」入口支持按应用开启保存，全部默认关闭。开启时保存当前内容，以后的刷新保留为独立批次；聊天还可按同一联系人连续查看。关闭后停止新增，已有历史可单独清空，不影响当前内容与独立的角色同步记忆。历史副本会增加本地存储，不额外调用 AI，也不会自动进入角色上下文。

在单个联系人聊天页点击「角色知晓」，可选择关闭、手动同步当前聊天或自动同步后续聊天；默认关闭，独立于「角色知晓用户窥屏」。可另行开启保留已同步旧内容，并设置每次聊天最多参考 1～200 条消息（默认 20）；同步会保存副本并增加聊天 Token。关闭同步会移除该联系人的同步副本。历史和同步信息随角色完整备份保存；旧版已覆盖且没有备份的内容无法恢复。

`node scripts/test-peek-history.mjs` 检查默认关闭、应用与角色隔离、刷新保存、权限与保存失败回滚。`node scripts/test-peek-history-browser.mjs` 使用隔离数据验证真实入口、历史切换、联系人同步和移动端／夜间布局；需要通过 `NODE_PATH` 提供 Playwright，`OVO_TEST_CHROMIUM` 可指定 Edge 或 Chrome 路径。

## 语音接入

在 API 设置的「语音合成」中，角色与用户可以分别选择 MiniMax、火山引擎或 ElevenLabs。ElevenLabs 填写 API Key 后，使用「选择」读取账号音色，或直接填写 Voice ID；模型已有默认值，也可以点击「读取」加载服务支持的模型。保存后可试听，聊天设置中的自定义音色优先于默认音色。

MiniMax 增加当前国内／国际官方地址，Group ID 可选；原有域名、模型、音色和预设仍保留。ElevenLabs 的音色和语速单独保存，切换回原服务后不会覆盖旧声音配置。自定义接口地址位于 ElevenLabs 的「高级设置」，可以指向兼容代理。导出的 TTS 预设不会包含 API Key。

`npm run test:tts` 检查语音请求、播放取消、队列、配置和预设兼容性；`npm run test:media` 检查原有媒体适配。
